# EcoPrompt Coach — audit (2026-06-20)

Scheduled routine pass: bug hunt, competitor review, roadmap to paid product. Core test suite: 14/14 passing. Web app boots cleanly. 21 models grade as expected. No XSS surface (all DOM via `textContent` / `createElement`).

## 1. Bugs verified (with repros)

### 1A. `ImpactEngine.gradeFor(NaN)` throws
- **File:** `packages/core/src/calculator.js:346` (and `apps/extension/background.js:22`)
- **Repro:** `engine.gradeFor(NaN)` → `TypeError: Cannot read properties of undefined (reading 'grade')`.
- **Impact:** a corrupted history entry (`energyWh = NaN`) crashes the service worker on badge render — the badge silently dies for that user.
- **Fix:** `const band = GRADE_BANDS.find(b => wh <= b.maxWh) || GRADE_BANDS[GRADE_BANDS.length - 1];` (same in `background.js`).

### 1B. "Trim & copy optimized prompt" can copy an empty string
- **File:** `packages/core/src/analyzer.js:259` `generateOptimizedPrompt()`
- **Repro:** input `"thanks"` / `"please"` / `"thank you"` / `"kindly"` → optimized = `""`.
- **Impact:** popup shows the trim button whenever `totalTokensSaved > 0` and never guards against an empty output. User clicks, pastes nothing, thinks the extension is broken.
- **Fix:** in `popup.js` `onTrimClick` (and analyzer), bail with a friendlier message when `optimized.length < 3` or only 1 token remains. Or never offer trim when the prompt is *only* courtesy.

### 1C. Task-type false positives
- **File:** `packages/core/src/analyzer.js:34-97`
- `"painting walls white"` → `IMAGE_GENERATION` (because `painting` is a keyword)
- any sentence containing `api` → `CODE_GENERATION` regardless of context
- **Fix:** tighten keyword lists; require co-occurrence with verbs (`generate`, `create`, `draw`) for `IMAGE_GENERATION`; treat `api` only when preceded by a coding verb. A small confidence-weighted scoring tweak is sufficient.

### 1D. Recorded history is forecast, not measurement
- **File:** `apps/extension/content.js:311` `recordSend()`
- `outputTokens` come from `analyzePrompt`'s *estimate* (typical task length), not the actual streamed response. Personal "impact" dashboards therefore display a smoothed forecast, not reality.
- **Options:**
  - (a) Snapshot the rendered assistant message after stream end (MutationObserver on the conversation root) and re-record actual tokens.
  - (b) Relabel the dashboard "Estimated impact" everywhere it's shown — currently we say "tracked", which overclaims.

### 1E. Hostname-only model detection
- **File:** `apps/extension/content.js:66`
- `chatgpt.com` always maps to `gpt-5`. If the user switches to GPT-5-thinking / o3 / 4.1-nano in the in-page menu, the pill grades wrong.
- **Fix:** scrape the model name from each site's header DOM (every site shows it), fall back to host.

### 1F. Empty-totals sentence is grammatically wrong
- `conversions.js forTotals()` with 0 queries returns *"Your 0 queries today used the energy of 0 seconds of an LED bulb..."*. UX nit — gate on `totals.queries > 0`, show different copy when empty.

### 1G. Token estimator runs ~25–30% high
- `estimateTokens("Could you please summarize the key findings of this report in plain language and structure it as bullet points organized by theme?")` → 33; real `cl100k` → ~26.
- README claims ±12% prose accuracy. Either re-tune the divisor (try 4.3 chars/token prose) or update the README.

### 1H. Service worker imports the whole calculator just for GRADE_BANDS
- `background.js` pulls `vendor/calculator.js` (80 KB) to read 5 constants. Extract `GRADE_BANDS` to `vendor/data/bands.json` (or a small `grades.js`) for faster SW cold-start.

## 2. Competitive landscape (mid-2026)

**Direct competitors (Chrome extension / web shelf):**
- **Carbon ScaleDown** — Chrome Web Store, live. Prompt optimization, 80% token-saving templates, team dashboards, "tree absorption" + "paper sheets" equivalences. The closest direct rival, already shipping team plans.
- **AI Impact Tracker** — simpler energy estimator on chat sites.
- **Chrome Carbon Tracker** — web-browsing carbon, broader scope, not LLM-specific.

**Enterprise wedge competitors:**
- **carbon-llm.com** — CO₂ per LLM call via token metadata, multi-tenant dashboards, CSRD/ESRS E1 exports. Direct competitor for the enterprise wedge; pitch is the EU AI Act Aug-2026 Article 11 hook.
- **Persefoni** (TIME GreenTech 2026), **Watershed** (Verdantix leader 2026), **CO2 AI** — $1B+ valuation carbon-accounting incumbents. They do **not** yet have first-class LLM-call accounting. That is the opening.

**Strategic read:** the consumer/extension space is small but crowded. The B2B space is wide open — incumbents have ESG breadth but no LLM depth; LLM startups have depth but no ESG distribution. EcoPrompt's defensible position is *"LLM-native accounting that exports CSRD / EU-AI-Act-ready, integrates with Watershed / Persefoni."*

## 3. What to build next (priority-ordered)

### P0 — Enterprise wedge (the only thing that drives ARR)
- **Server-side ingestion.** Small Node/Edge backend accepting `{workspace_id, model, in_tokens, out_tokens, region, ts}` from:
  - OpenAI / Anthropic / Bedrock / Vertex usage APIs (pull job, no user setup)
  - SDK wrappers in 5 languages (drop-in for `langchain`, `openai`, `anthropic`)
  - LiteLLM / OpenRouter gateway adapter
  The engine already does the math — just needs a hosted endpoint.
- **Per-workspace dashboard:** stack-rank teams and prompts by Wh / CO₂ / $; drill into top-100 wasteful prompts of the month.
- **CSRD / EU AI Act Article 11 report export.** PDF + CSV for sustainability leads to hand to auditors. carbon-llm.com sells this — build it better and integrate with Watershed / Persefoni via partner APIs.
- **Dollars + watt-hours side-by-side.** CFOs already approve cloud-cost dashboards; bundling carbon Trojan-horses into procurement.

### P1 — Conversions to paid
- **Gateway proxy SDK** that auto-rewrites courtesy phrases, caps output tokens, downshifts model when category allows, dedupes near-cache-hits. Bill on "% saved" — measurable ROI. This is where the analyzer becomes a money-maker, not a tip-giver.
- **Verified provider mode.** Pull true per-prompt figures from Google (already public) and OpenAI when available; stamp "verified" badge.
- **Slack + Teams weekly recap bot.** Free for individuals, paid for orgs. Habit-forming, viral within companies.

### P2 — Consumer growth (cheap, viral)
- **Shareable impact card.** "I cut 38% of my AI footprint this week — try EcoPrompt" with auto-generated image.
- **Edge / Firefox / Arc / Safari parity.** Chrome-only loses ~35% of potential users.
- **Mobile app — finish or delete.** Currently 5 stub screens with `TODO` comments. The README/roadmap claims more than the code delivers.
- **Pre-optimized prompt marketplace** tagged by grade, niche (sales, support, code review). Carbon ScaleDown does this; match or exceed.

### P3 — Differentiation moats
- **Region-aware grid factor per Azure/AWS region the workload actually runs in** — not provider averages. Auto-detected via the API key's deployment region. Nobody does this well.
- **Time-of-day grid CIF** (kWh emissions vary up to 5× intra-day). Schedule batch inference at clean hours.
- **On-prem grid factors for self-hosted Llama / Mistral** — opens regulated-industry market (banks, government).
- **ChatGPT Atlas / Perplexity Comet / Claude for Chrome integration** — AI browsers ship in 2026; be a first-party sidebar.

## 4. UI / UX quick wins (low effort, visible)

- Extension popup has no dark mode (web app does). Inherit `prefers-color-scheme`.
- Floating pill on chat pages can cover the send button on narrow viewports; clamp to a min-width safe zone.
- Add a per-prompt history view — users want to see *which* of their prompts were grade E.
- Onboarding tour the first time the popup opens (3 cards: type → pick model → see grade).
- Demo strip on the homepage rotates every 5.5 s — add play/pause.
- "How many trees offset this?" equivalence — most-shared single stat in this category.
